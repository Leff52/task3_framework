##  Ключевые компоненты

### Конфигурация

**C#:**
- `AppOptions` - модель конфигурации
- `AppMode` enum - режимы работы
- `AppOptionsValidator` - валидация параметров
- `RateLimitOptions` - настройки дросселирования

**Node.js:**
- `buildConfig()` - построение конфига с приоритетом
- `validateConfig()` - валидация всех параметров
- `getMode()`, `getPort()`, `getTrustedOrigins()` - экстракторы

### Безопасность

**C#:**
- `SecurityHeadersMiddleware` - защитные заголовки
- `ErrorHandlingMiddleware` - обработка ошибок с режимами
- CORS Policy "TrustedOrigins"
- RateLimiter policies: "read", "write"

**Node.js:**
- `applySecurityHeaders()` - добавляет защитные заголовки
- `applyCors()` - CORS с доверенными источниками
- `createRateLimiter()` - drosselierung per IP
- Mode-aware error messages в server.js

### Тесты

**Node.js - 9 тестов:**
1. Приоритет источников конфигурации
2. Валидация некорректных параметров
3. CORS - недоверенный источник
4. CORS - доверенный источник
5. Rate limiting - основной
6. Rate limiting - read/write разделение
7. Защитные заголовки
8. Интеграция - доверенный источник
9. Интеграция - недоверенный источник

**C# - Архитектура тестов:**
- ConfigurationPriorityTests - приоритет конфига
- IntegrationSecurityTests - CORS, Rate limiting, заголовки (использует WebApplicationFactory)

##  Как использовать проект

### Проверка

```bash
# Проверка Node.js тестов
cd node
npm install
npm test

# Проверка C# приложения
cd csharp/src/Pr3.ConfigAndSecurity
dotnet run
# (запустится на https://localhost:5000)

# Проверка валидации
dotnet run -- --origins=""
# (выведет ошибку и не запустится)
```

### Почему именно эта архитектура?

1. **Fail-fast** - обнаружение проблем ДО запуска экономит часы на production
2. **Explicit config** - порядок приоритета явный, без сюрпризов
3. **Validation first** - никогда не запустится с bad конфиг
4. **Defense in depth** - несколько слоёв защиты
5. **Mode-aware** - информация об ошибках зависит от режима
