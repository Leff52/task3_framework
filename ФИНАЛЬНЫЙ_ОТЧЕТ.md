### 4.  Rate Limiting (ограничение частоты запросов)

**Реализовано:**
- **C#:** [Program.cs](csharp/src/Pr3.ConfigAndSecurity/Program.cs#L52-L90) - ASP.NET Core RateLimiter с двумя policies (read/write)
- **Node.js:** [security.js](node/src/security.js#L20-L59) - createRateLimiter с fixed window per IP

**Механизм:**
```
- Fixed Window для каждого IP адреса
- Отдельные счётчики для READ и WRITE запросов
- Окно сброса: 1 минута
- К READ применяется lim readPerMinute
- К WRITE применяется limit writePerMinute
- При превышении: HTTP 429 Too Many Requests
```

**Примеры:**
```
ReadPerMinute: 60    → 60 GET запросов в минуту на IP
WritePerMinute: 20   → 20 POST запросов в минуту на IP
```

**Маршруты сRate Limiting (C#):**
```csharp
GET /api/items               .RequireRateLimiting("read")
GET /api/items/by-id/{id}    .RequireRateLimiting("read")
POST /api/items              .RequireRateLimiting("write")
GET /api/mode                .RequireRateLimiting("read")
```

**Проверено тестами:**
-  Node.js: "Ограничитель частоты блокирует лишние запросы" ✔
-  Node.js: "Ограничитель отдельно считает read и write" ✔
-  Node.js: "Защитные заголовки добавляются" ✔

### 5.  Защитные заголовки ответа (минимум 4)

**Реализовано:**
- **C#:** [SecurityHeadersMiddleware.cs](csharp/src/Pr3.ConfigAndSecurity/Middlewares/SecurityHeadersMiddleware.cs)
- **Node.js:** [security.js](node/src/security.js#L1-L5)

**Добавляемые заголовки:**

| Заголовок | Значение | Назначение |
|-----------|----------|-----------|
| `X-Content-Type-Options` | `nosniff` | Предотвращает MIME-sniffing атаки, заставляет браузер использовать указанный Content-Type |
| `X-Frame-Options` | `DENY` | Предотвращает Clickjacking - запрещает встраивание страницы в iframe |
| `Cache-Control` | `no-store, max-age=0` | Запрещает кэширование (критично для auth/sensitive данных) |
| `Pragma` | `no-cache` | Legacy заголовок для старых прокси, аналог Cache-Control |

**Проверено тестами:**

### 6.  Два режима работы (Учебный и Боевой)

**Реализовано:**
- **C#:** [AppMode.cs](csharp/src/Pr3.ConfigAndSecurity/Config/AppMode.cs) enum + [ErrorHandlingMiddleware.cs](csharp/src/Pr3.ConfigAndSecurity/Middlewares/ErrorHandlingMiddleware.cs#L34)
- **Node.js:** [server.js](node/src/server.js#L83-L86)

**Учебный режим (Development):**
```json
{"code": "bad_request", "message": "Поле name не должно быть пустым", "requestId": "abc123"}
```
- Полная информация об ошибке
- Помогает в отладке
- По умолчанию в appsettings.json

**Боевой режим (Production):**
```json
{"code": "bad_request", "message": "Ошибка обработки запроса", "requestId": "abc123"}
```
- Минимальные детали об ошибке
- Не раскрывает внутреннюю информацию
- Безопасно для production

**Переключение режима - только через конфигурацию:**
```bash
# C#
dotnet run -- --mode=Боевой

# Node.js
APP_MODE=боевой npm start
```

**Проверено:**
-  app.Mode enum содержит оба режима
-  ErrorHandlingMiddleware использует режим для форматирования сообщений
-  Конфигурация правильно переключает режимы

### Безопасность

1. **Fail-fast** - Проблемы в конфиге обнаруживаются ДО запуска
2. **Defense in depth** - Несколько слоёв защиты (валидация → CORS → Rate limit → headers)
3. **Secure by default** - Консервативные настройки в appsettings.json
4. **No silent failures** - Четкие сообщения об ошибках
5. **Mode-aware** - Информация об ошибках скрывается в production
